# dev-onboarding-lab

開発の流れ（Issue → ブランチ → PR → CI → レビュー → マージ）と、リポジトリの設定を、**壊してよい環境**で体験するための練習用リポジトリです。

> **状態: 草案。** M0〜M10 の資料と、演習の題材（M4 と M7 の `app/`、M10 の `worker-template/`）があります。全体の計画は [docs/course-map.md](docs/course-map.md) を参照してください。

## このコースの姿勢: コードは、ほとんど書きません

このコースは、**プログラミングを学ぶコースではありません**。チームで開発するための、**道具の使い方に慣れ、判断できるようになる**ことが、目的です。

- **書くのは、ほとんど、手順書にある短い文や設定**（Issue、PR の説明、設定ファイルの数行、テストの数行など）です。
- **コードは、AI と一緒に、読む・動かす・壊して、直す**ためのものです。自分で、ゼロから書くことは、ありません。
- 身につけるのは、**道具を使う手の感覚**（Git、GitHub、CI、テスト、AI）と、**確かめる習慣**（差分を読む、効いているかを確かめる）、**分からないことを言葉にする力**です。
- 「コードが上手に書けない」ことは、心配いりません。**分からないことを、分からないと言い、AI に自分の言葉で質問して、理解を積み上げられる**ことが、大切です。

## 使い方: 読む場所と手を動かす場所

| | 場所 | 役割 |
|---|---|---|
| **読む** | 講師から案内される、組織のこのリポジトリ | 手順書の**最新版**。内容が直されることがあるので、こちらを読む |
| **手を動かす** | あなた自身のリポジトリ | このリポジトリを**テンプレートとして複製**したもの。あなたが**オーナー** |

自分のリポジトリにも手順書のコピーが入りますが、それは複製した時点のものです。**正は、組織のリポジトリ**です。

## 自分のリポジトリを作る

1. GitHub のアカウントを用意する（**2段階認証を有効にしたもの**）。
2. このリポジトリの画面で「**Use this template**」→「Create a new repository」を選ぶ。
3. 所有者は**自分のアカウント**、公開範囲は **Private（非公開）** にして作成する。
4. 作成したリポジトリを、自分のパソコンにクローンする（手順は、[M1 Git とブランチの基本](modules/m1-git-basics/README.md)の「準備」）。
5. 自分のリポジトリの「Issues」→「Labels」で、`exercise` と `task` のラベルを作る（演習の記録・作業の Issue に付くラベルです。**テンプレートからは、ラベルは複製されません**）。

## このリポジトリの約束

- ここは練習の場です。**失敗してかまいません**（むしろ、わざと失敗させる演習があります）。
- 本物の秘密（パスワード、API キー、トークン）、個人情報、実際の業務のデータを、**絶対に入れない**でください。演習で使う偽の秘密は、その場で生成します。
- 各演習には「答え」があります。行き詰まったら見て、考えてかまいません。ただし、最後に**講師との面談で、自分の言葉で説明してもらいます**。
- 分からないことを「分かったふり」で進めないでください。質問することが、最初の仕事です。

## 準備するもの

- Node.js 22 以上、Git
- エディタ（VS Code など）
- **AI エージェントの契約**（**M2 から**必要。**費用は本人の負担**）。**Claude Code を推奨**、Codex も使えます。導入は [M2](modules/m2-ai-learning/README.md) を参照
- Docker Desktop（**M7 以降**で必要。M0〜M6 では不要）。空き容量 10GB 以上、メモリ 8GB 以上が目安

## 構成

```
modules/                各モジュール（手順書・演習・答え）
  m4-pr-and-ci/app/     M4 の演習の題材になる小さなアプリ（独立した package.json を持つ）
  m7-local-env/app/     M7〜M9 が共有する、ローカルの Supabase を使う小さなアプリ
docs/                   コース全体図
.github/                PR テンプレート、Issue フォーム、CI
```

モジュールの題材は、それぞれ `modules/<名前>/` の中に独立して置きます（他のモジュールの依存関係や CI に影響しないようにするため）。
