# コース全体図

「1つの変更が、思いついてから本番に届くまで」を軸に、**学習する順に**モジュールを並べます（番号が、そのまま学習順です）。

```
分からないと言う・最小単位で理解する（M0）→ Git の基本（M1）→ AIと学ぶ（M2）
   → Issue(何を・なぜ) → PR → CI → レビュー → リポジトリの設定 → AIを統制する（M3〜M6）
   → 手元で動かす → テスト（M7〜M8）
   → 守る（セキュリティ）→ デプロイ → 本番（M9〜M10）
```

## このコースで身につけること（コードは、ほとんど書きません）

プログラミングを学ぶコースではなく、**チームで開発するための道具の使い方に慣れ、判断できるようになる**コースです。書くのは、ほとんど、手順書にある短い文や設定で、コードは、AI と一緒に**読む・動かす・壊して直す**ためのものです。身につけるのは、**道具を使う手の感覚**（Git、GitHub、CI、テスト、AI）、**確かめる習慣**、**分からないことを言葉にする力**、**安全に使う判断**です。

## AI を使うことについて

- **使う AI**: **Claude Code を推奨**します。コマンドの実行を、許可の仕組みで**物理的に統制できる**ためです。**Codex も使えます**（M6 の対応表で、対応する機能を補います）。
- **指示の出し方**: ローカル AI エージェントの**チャット画面**に、**自分の言葉（日本語の普通の文章）**で書くことを基本とします。コマンドや決まった書き方は、覚えなくてよい。分からないことは、**まず AI に、自分の言葉で質問**します（M0）。
- **費用**: 学生本人の負担です。
- **読ませてよい範囲**: **コードは、読ませてよい**。本番の**個人情報**と、各種の **API キー・秘密**は、**禁止**です（そもそも、物理的にアクセスできない形にします）。
- **順序の考え方**: AI は全モジュールで使うので、**M2 で、先に基本を学びます**（AI を先生として使う、確認画面を読む）。許可の設定や worktree は、ブランチと PR を知らないと意味が分からないため、**M4・M5 のあとの M6** で学びます。

## 設計の方針

- **分からないと言う、小さく分けて理解する。** 理解の入り口を、最初に教える。AI は、その手助けとして使う。
- **同じ題材を使い回す。** 演習は、小さなアプリを題材にし、モジュールをまたいで同じ構造に触れる。
- **理由を説明させる。** 手順の暗記ではなく、「これが無かったら何が起きるか」を言葉にさせる。最後は、面談（諮問）で確認する。
- **答えは見せる。** 行き詰まったら答えを見て考えてよい。理解しているかは、面談で確かめる。
- **予想は、AI を使わず、自分の力で書く。** AI は、予想のあとに、理解を深めるために使う。
- **実運用の秘密・個人情報は持ち込まない。** このリポジトリは、構造を学ぶための縮小版である。
- **各モジュールの題材は独立させる。** 他のモジュールの依存関係や CI に影響しないよう、`modules/<名前>/` の中に置く。
