# M1-2 の答えと解説

> 先に、自分の予想と観察を書き残してから読んでください。表示の文は、Git のバージョンや言語設定で、少し違うことがあります。この手順は、使い捨てのリポジトリと、ローカルのリモート（GitHub の代わり）で、実際に動作を確認しています。GitHub の画面の操作は、確認していません（画面の表記は、変わることがあります）。

## 予想と結果

### ヒント

- ブランチは、**履歴の別の流れ**。ブランチごとに、ファイルの中身が、切り替わる。
- コミットは、自分のパソコンの中の、記録。

### 答え

| 手順 | 表示と、意味 |
|---|---|
| 2: `git switch -c practice/git-2` | `Switched to a new branch 'practice/git-2'`（新しいブランチを作って、移った） |
| 3: 編集後の `git status` | `Changes not staged for commit` と `modified: ...diary.md`（**変更したが、まだ add していない**） |
| 4: `git add` のあと | `Changes to be committed`（**記録待ち**）。`modified:` が、別の欄に移る |
| 5: `git commit` | `[practice/git-2 xxxxxxx] practice: 日記に1行足す` と `1 file changed, 1 insertion(+)`。`git log --oneline` の先頭に、**自分のコミット**が増える |
| 6: `git push -u origin practice/git-2` | `* [new branch] practice/git-2 -> practice/git-2`（GitHub に、新しいブランチができた）。`set up to track` は、「このブランチは、GitHub の同名のブランチと対応する」という意味 |
| 8: `git switch main` | `Switched to branch 'main'`。**日記から、足した 1 行が消える**（`main` には、その変更が入っていないため） |

### GitHub の画面（手順 7）

- ブランチを `practice/git-2` にすると、`diary.md` に**足した 1 行がある**。
- ブランチを `main` にすると、**足した 1 行はない**。

**変更は、ブランチごとに、独立しています。** `main` は、触っていないので、変わりません。

## 手順 9: 考える

- **ブランチで作業する理由**: `main` は「正とする流れ」で、他の人も、これを土台にする。そこに、直接、試しの変更を入れると、**壊れた状態が、みんなに影響する**。ブランチで試せば、**失敗しても、捨てるだけ**で済む。気に入った変更だけを、あとで `main` に合わせる（M4 の PR）。
- **`add` と `commit` を分ける利点**: **何を記録するかを、選べる**。たとえば、複数のファイルを変更したとき、関係のあるものだけを、1 つのコミットにまとめられる。
- **`push` するまで、他の人に見えないこと**: **コミット**（自分のパソコンの中の記録）。`push` して初めて、GitHub に送られ、他の人に見える。

## 振り返りの答え

- **コミットした変更の、記録場所**: **自分のパソコン**の、リポジトリの履歴。`push` の前は、**自分のパソコンにしか**ない。`push` の後は、**GitHub にも**ある（バックアップにもなる）。
- **`git switch main` で日記の中身が変わった理由**: ブランチごとに、**ファイルの内容**が、記録されているから。`switch` は、「作業フォルダのファイルを、そのブランチの状態に、切り替える」操作。
