# M1-3 の答えと解説

> 先に、自分の予想と観察を書き残してから読んでください。この手順（`restore`、`revert`）は、使い捨てのリポジトリで、実際に動作を確認しています。

## 手順 2: A（`restore`）

### 答え

`git restore <ファイル>` で、**足した間違いの 1 行は、消えます**。`git status` は、きれいな状態に戻ります。**コミットしていない**変更なので、履歴にも残りません。**取り消せません。**

## 手順 3: B（`revert`）

### ヒント

- `revert` は、「消す」のではなく、「**打ち消す内容の、新しいコミットを作る**」。

### 答え

`git revert HEAD --no-edit` のあと、`git log --oneline` は、次のようになります（識別子は、人によって違います）。

```
ecc3733 Revert "practice: 間違った記録"
e09e911 practice: 間違った記録
5fcf84c practice: 日記に1行足す
...
```

- **履歴に、1 つ、コミットが増えた**（`Revert "…"` という、打ち消しのコミット）。
- `diary.md` の、間違いの 1 行は、**消えた**。
- **元の「間違った記録」のコミットは、履歴に残っている**。

## 手順 4: C（危険なコマンド）

### 答え

| コマンド | 何を失わせるか |
|---|---|
| `git reset --hard` | **まだコミットしていない変更**が、すべて消える。指定の仕方によっては、**コミットも消える** |
| `git push --force` | GitHub の履歴を、**自分の履歴で上書き**する。**他の人のコミットが、消える**ことがある |
| `git clean -f` | Git が管理していない（未追跡の）**ファイルが、削除される** |
| `git branch -D practice/git-2` | **マージされていなくても**、ブランチを消す。**そのブランチにしかない作業が、失われる** |

どれも、**取り消しにくい**操作です。**実行する前に、`git status` と `git log --oneline` で、何が失われるかを、確かめます。**

## 手順 5: 考える

- **`restore` と `revert` の違い**:
  - `restore` は、**コミットしていない**変更を、**捨てる**。履歴に**何も残らず**、取り消せない。
  - `revert` は、**コミットした**変更を、**打ち消す、新しいコミット**を作る。**履歴は、残る**（元のコミットも、打ち消しのコミットも）。あとから、経緯を追える。
- **危険なコマンドを、AI が提案してきたら**: **許可しません**。なぜその方法が必要なのかを、チャットで聞き、**別の安全な方法**（`revert` など）がないかを、相談する（[M6](../../m6-ai-control/README.md) の許可カードと同じ考え方）。

## 振り返りの答え

- **「消す」と「打ち消す」の違い**: 「消す」は、履歴ごと**なかったことにする**（取り戻せない）。「打ち消す」は、**履歴に残したまま、内容だけを元に戻す**（経緯が残り、取り消しも、またできる）。`revert` が安全なのは、**何も失わない**から。
- **戻したいとき、最初に確かめること**: **今の状態**。`git status`（何が変わっているか）と、`git log --oneline`（どのコミットがあるか）。状態を確かめずに戻すと、**意図しないものまで、失う**ことがある。
