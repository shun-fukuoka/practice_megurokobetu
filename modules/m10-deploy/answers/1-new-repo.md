# M10-1 の答えと解説

> 先に、自分の予想と観察を書き残してから読んでください。ローカルでの手順（`npm ci`、`npm run check`、`npm run dev`、`npm run deploy:dry`）は、教材の作成時に、実際に確かめています。

## 予想と結果

### ヒント

- 「ローカル」は、どのコンピューターの中の話か。
- `deploy:dry` の `dry` は、「空打ち」の意味。

### 答え

| 問い | 答え |
|---|---|
| ローカルで動かす／公開する の違い | ローカルは、**自分のパソコンの中だけ**で動く（自分しか見られない）。公開（デプロイ）は、**インターネット上のサーバーに置き**、誰でも URL で見られるようにすること |
| `npm run deploy:dry` で起きること | **設定とコードを検証し、アップロードの内容を表示するだけ**。**公開はされない**。Cloudflare のアカウントも、使わない |
| 別のリポジトリにする理由 | 独立したアプリは、**変更の履歴・権限・秘密（Secrets）・自動化の設定**を、**そのアプリだけで**管理したいから。コース全体のリポジトリに混ぜると、無関係な変更や権限が、混ざる |

### 手順 4 の確認

- `http://127.0.0.1:8787/` は、**自分のパソコンだけ**からアクセスできる（`127.0.0.1` は、自分自身を指す住所）。
- 公開した場合の住所（`workers.dev`）とは、**別物**。

### 手順 6・7 の答え

- `wrangler.jsonc` に書かれているのは、**Worker の名前、入口のファイル、実行環境の版**。**秘密は、ない**。
- `deploy.yml` の、`${{ secrets.CLOUDFLARE_API_TOKEN }}` と `${{ secrets.CLOUDFLARE_ACCOUNT_ID }}` が、**Secrets を参照している場所**。**値そのものは、書かれていない**。値は、**GitHub の Secrets** に、ある。

## 振り返りの答え

- **ローカルと公開の違い**: 誰が見られるか、どこで動くか。ローカルで試して、問題がなければ、公開する。
- **別のリポジトリにする理由**: 上の表のとおり。

## 補足

- 作った直後に、`Deploy` が**失敗している**のは、Secrets が、まだないため。**Secrets を登録すれば、解消する**（演習 2 と 3）。
- `npm ci` は、`package-lock.json` に**記録されたとおりの版**を入れる。`npm install` は、記録を更新することがある。CI では `npm ci` を使う（M4）。
