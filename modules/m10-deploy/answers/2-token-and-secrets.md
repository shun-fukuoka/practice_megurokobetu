# M10-2 の答えと解説

> 先に、自分の予想と観察を書き残してから読んでください。この演習は、Cloudflare と GitHub の**実際の画面**を使うので、**教材の作成時には、実際には確かめていません**（画面の名前は変わることがあります）。違うときは、公式の資料か、講師に聞いてください。

## 予想と結果

### ヒント

- 漏れたときの被害は、**トークンが持つ力**で決まる。
- Secrets は、**書き込み専用**の金庫のようなもの。

### 答え

| 問い | 答え |
|---|---|
| 全部の権限・範囲で作ると、漏れたとき、どうなるか | 攻撃者が、**そのアカウントの、あらゆる資源**（他の Worker、データ、設定）を、**書き換え・削除**できてしまう。**被害が、最大になる** |
| Secrets の値を、画面で見られるか | **見られない**。更新（上書き）か削除だけできる |
| コードに書かず、Secrets に置く理由 | コードは、**履歴に残り、多くの人に見える**（リポジトリを共有した人、過去の履歴）。一度、載せると、**消しても、履歴に残る**。Secrets なら、**値が、コードや履歴に出ない** |

### 手順 7 の答え

- **「Edit Cloudflare Workers」で、範囲を 1 アカウントに絞る理由**: **公開に必要な力だけ**にして、漏れたときの被害を、**小さくする**（最小権限）。
- **値を見られない利点**: 画面の覗き見、画面共有、スクリーンショット、操作ミスで、**値が出るのを防げる**。
- **誰が使えるか**: **このリポジトリのワークフロー**が、`main` への変更で動くときに使う。リポジトリに書き込める人が、ワークフローを変えれば、**トークンを使える**ので、**書き込み権限を持つ人は、信頼できる人に限る**。使っているのは、`deploy.yml` の、`Deploy Worker` ステップ（`apiToken:` と `accountId:`）。

## 振り返りの答え

- **気をつけたこと**: 値を、画面共有・チャット・AI・メモ帳に出さない。クリップボードから、そのまま貼る。範囲と権限を、絞る。
- **M5 の練習が役立った点**: 偽の値で、**登録の操作と、名前の合わせ方**に慣れていたので、本物でも、**落ち着いて**、正しい名前で登録できる。

## 補足

- `CLOUDFLARE_ACCOUNT_ID` は、トークンほど強くはないが、**不必要に公開しない**。
- **漏れたかもしれない**と思ったら、**すぐ**に、そのトークンを失効し、新しく作り直して、Secrets を更新する。
