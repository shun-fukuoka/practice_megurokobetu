# 演習 M10-1: 新しいリポジトリを作る

所要時間の目安: 30 分 / 対象: 全員 / 前提: [README](../README.md) の準備（GitHub アカウント、Node.js、Git）

## 目的

- コース全体のリポジトリとは**別の、新しいリポジトリ**を作る（独立したアプリは、別のリポジトリで管理する）。
- 小さな Worker を、**ローカルで動かして**、公開せずに、動作と設定を確かめる。

> コードは書きません。コマンドを実行して、画面を確認するだけです。

## 手順

### 0. 記録の Issue を作り、予想を書く（自分の力で）

[演習の進め方（M0 の 3b）](../../m0-orientation/README.md)に従い、**これまでのコース用のリポジトリで**、「演習の記録」の Issue（演習: `M10-1`）を作ります。次の予想を、**実行する前に**書いてください。

1. 「ローカルで動かす」ことと、「公開する（デプロイ）」ことは、何が違うか。
2. `npm run deploy:dry` を実行すると、何が起きると思うか（公開されるか）。
3. このアプリを、コース全体のリポジトリの中に置かず、**別のリポジトリ**にするのは、なぜか。

### 1. 新しいリポジトリを作る

**講師が、`worker-template/` の中身を、テンプレートリポジトリとして公開している場合**（講師から案内されます）:

1. そのテンプレートリポジトリの画面で、「**Use this template**」→「Create a new repository」を選ぶ。
2. 所有者は**自分のアカウント**、名前は `hello-worker-practice`、公開範囲は **Private（非公開）** にして、作成する。

> テンプレートが、まだ公開されていない場合は、講師に相談してください（コース全体のリポジトリの、`modules/m10-deploy/worker-template/` の中身を、新しいフォルダにコピーして、新しいリポジトリとして作る方法もあります。その場合は、講師の案内に従ってください）。

### 2. クローンして、依存関係を入れる

```bash
git clone <自分の新しいリポジトリの URL>
cd hello-worker-practice
npm ci
```

### 3. 型検査とテスト

```bash
npm run check
```

「8 pass」と表示されることを確認します。

### 4. ローカルで起動する

```bash
npm run dev
```

ブラウザで、次を開きます（`npm run dev` は、起動したままにします）。

| 場所 | 確認すること |
|---|---|
| http://127.0.0.1:8787/ | 「こんにちは、はじめまして！」と「版: v1」 |
| http://127.0.0.1:8787/?name=花子 | 「こんにちは、花子 さん！」 |
| http://127.0.0.1:8787/health | `{"ok":true,"version":"v1"}` |

確認したら、**Ctrl+C** で止めます。

### 5. 公開せずに、設定を検証する

```bash
npm run deploy:dry
```

「`Total Upload`」「`--dry-run: exiting now.`」のような表示が出ることを確認します。**公開は、されていません**（Cloudflare のアカウントも、使っていません）。

### 6. 設定ファイルを読む

エディタで、次を開いて、読みます。

- `wrangler.jsonc`: **秘密（トークンなど）が、書かれていない**ことを確認する。何が書かれているか（名前、入口、実行環境の版）。
- `.github/workflows/deploy.yml`: どんなときに動くか（`main` に変更が入ったとき）。`secrets.` で始まる部分は、どこか。

### 7. 考える

- `npm run dev` は、**誰が**見られるか（自分のパソコンの中だけか、インターネットか）。
- `deploy.yml` の中に、トークンの**値そのもの**は、書かれているか。値は、どこにあるのか。

### 8. 片づけの確認

`npm run dev` を止めた状態で、`git status` を実行し、**何も表示されない**こと（ローカルでの確認では、ファイルを変更していません）。

> **メモ**: 新しいリポジトリを作った直後に、GitHub の「Actions」タブで、`Deploy` ワークフローが**失敗**していることがあります。**Secrets をまだ登録していない**ためで、この時点では**自然**です（演習 2 で登録します）。失敗したログを開いて、**どこで、なぜ失敗したか**を、読んでみてください。

## 振り返り
