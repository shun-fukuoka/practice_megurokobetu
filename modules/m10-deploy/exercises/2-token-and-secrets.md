# 演習 M10-2: トークンと Secrets

所要時間の目安: 30 分 / 対象: L1 / 前提: [演習 1](1-new-repo.md)

## 目的

- 自分の Cloudflare アカウントで、**最小限の権限・範囲の API トークン**を作る。
- トークンを、**自分のリポジトリの Secrets に、安全に登録**する。

> **これは、本物の鍵の操作です。** M5 の練習（偽の値）と違い、トークンの値は、**あなたのアカウントで、公開（デプロイ）できる力**を持ちます。**画面共有、スクリーンショット、チャット、AI、メモ帳に、値を出さない**でください。
>
> 画面の名前や場所は、Cloudflare や GitHub の更新で、変わることがあります。違うときは、**公式の資料**（Cloudflare の「GitHub Actions」のページ）を見るか、講師に聞いてください。

## 手順

### 0. 記録の Issue を作り、予想を書く（自分の力で）

[演習の進め方（M0 の 3b）](../../m0-orientation/README.md)に従い、「演習の記録」の Issue（演習: `M10-2`）を作ります。次の予想を、**実行する前に**書いてください。

1. トークンを、**全部のアカウント・全部の権限**で作ったら、漏れたときに、何が起きるか。
2. Secrets に登録したあと、**値を、画面で見られるか**。
3. このトークンを、**コードや設定ファイルに直接書く**代わりに、Secrets に置くのは、なぜか。

### 1. Cloudflare のアカウントを用意する

<https://dash.cloudflare.com/> で、アカウントを作ります（無料）。**2 段階認証を、有効にすることをおすすめします。**

### 2. workers.dev のサブドメインを確認する

`workers.dev` のアドレス（`https://<Worker の名前>.<サブドメイン>.workers.dev`）を使うには、**アカウントに、サブドメインが登録されている**必要があります。ダッシュボードの **Workers & Pages** の画面で、**登録の有無を確認し、まだなら登録**します（公式の資料に、「各アカウントに、`workers.dev` のサブドメインがあり、ダッシュボードで設定できる」と書かれています）。登録した**サブドメインの名前**を、メモします（秘密ではありません）。

### 3. アカウント ID を調べる

公式の「Find account and zone IDs」の案内に従って、**アカウント ID** を調べます。値は、**手順 5 で使う**ので、次の画面を開くまで、**自分の目で見るだけ**にします（他の人に見せない）。

### 4. API トークンを作る

ダッシュボードで、**Account API tokens**（アカウントの API トークン）の画面を開き、次のように作ります（公式の資料の手順です）。

1. **Create Token** を選ぶ。
2. 画面に並ぶ**テンプレート**の一覧から、**Edit Cloudflare Workers** を選ぶ（**Custom で、権限を一つずつ組み立てる必要はありません**）。選ぶと、Worker のデプロイに使う権限（Workers Scripts、Workers KV Storage、Workers R2 Storage、Workers Tail、Account Settings、Workers Routes）が、まとめて設定されます。
   - このテンプレートは、今回のデプロイだけに必要な権限より、**少し広め**です。それでも、公式が用意した標準のテンプレートなので、まずはこれを使います。
   - なぜ「テンプレート」を使うのか、**自分の言葉で説明できる**ようにしておきます（権限の選び間違い・付け忘れを避けられる、など）。
3. 名前を付ける（例: `m10-practice-deploy`。何のためのトークンか、分かる名前）。
4. **範囲を、最小限に絞る**（たとえば、**自分のアカウント 1 つだけ**）。
5. 作成する。

作成直後の画面に、**トークンの値**が表示されます。**この画面を閉じると、見られなくなることが多い**ので、**次の手順で、すぐに、登録**します。

> **値を、どこにも書き写さないでください。** 画面から、コピー（クリップボード）して、貼り付けるだけにします。

### 5. GitHub の Secrets に、登録する

自分の `hello-worker-practice` リポジトリの、**Settings** → **Secrets and variables** → **Actions** → **New repository secret** で、次の 2 つを登録します。

| 名前（Name） | 値（Secret） |
|---|---|
| `CLOUDFLARE_API_TOKEN` | 手順 4 の、トークンの値 |
| `CLOUDFLARE_ACCOUNT_ID` | 手順 3 の、アカウント ID |

> 名前は、**そのとおりに**（大文字と小文字、アンダースコアに、注意）。`deploy.yml` が、この名前を使います。

### 6. 確認する

- Secrets の一覧に、**2 件**が表示されること。
- 登録した値を、**画面で見られない**こと（更新はできても、読み出せない）。

### 7. 考える

- トークンの権限を、「Edit Cloudflare Workers」で、範囲を「自分のアカウント 1 つ」に絞ったのは、なぜか。
- Secrets の値を、あとから見られないことの利点は、何か。
- このトークンは、**誰が**使えるか（誰の操作で、使われるか）。`deploy.yml` の、どの部分で使われているか。

### 8. 片づけ

特にありません（トークンの**削除は、演習 5 で行います**）。
