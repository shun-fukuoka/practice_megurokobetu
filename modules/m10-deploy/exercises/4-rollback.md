# 演習 M10-4: ロールバック

所要時間の目安: 25 分 / 対象: L1 / 前提: [演習 3](3-pr-to-deploy.md)（v2 が公開されていること）

## 目的

- 公開した版を、**前の版に戻す**操作を体験する。
- 戻したあと、**Git の `main` と、公開されているものが、ずれる**ことを、確かめる。
- **ずれを直す**（正しい版を、再度公開する）。

> コードは書きません。ダッシュボードの操作と、確認だけです。

## 手順

### 0. 記録の Issue を作り、予想を書く（自分の力で）

[演習の進め方（M0 の 3b）](../../m0-orientation/README.md)に従い、「演習の記録」の Issue（演習: `M10-4`）を作ります。次の予想を、**実行する前に**書いてください。

1. ロールバックすると、公開されている版は、**どのくらいの時間で**切り替わるか。
2. ロールバックしたあと、Git の `main` の `VERSION` は、どうなるか。
3. ロールバックは、**問題の根本的な解決**になるか。

### 1. 今の版を確認する

ブラウザで、`https://hello-worker-practice.<サブドメイン>.workers.dev/health` を開き、`version` が `v2` であることを確認します。

### 2. ダッシュボードで、ロールバックする

1. Cloudflare のダッシュボードで、**Workers & Pages** を開き、自分の Worker（`hello-worker-practice`）を選ぶ。
2. **Deployments**（デプロイの履歴）を開く。**版の一覧**が、表示される。
3. **v1 だった、古い版**の行の「**…**」（三点のアイコン）を押し、**Rollback** を選ぶ。確認の表示が出たら、内容を読んで、進める。

### 3. 戻ったことを確認する

もう一度、`/health` を開きます（再読み込み）。`version` は、何になりましたか。**どのくらいで、切り替わりましたか。**

### 4. ずれを確かめる

自分のターミナルで、次を実行し、**`main` の `VERSION`** を確認します。

```bash
git switch main
git pull
git log --oneline | head -3
```

エディタで `src/greeting.ts` を開き、`VERSION` が、`v2` のままであることを確認します。

**公開されている版（v1）と、`main` の版（v2）は、同じですか。** 記録の Issue に、書き留めます。

### 5. 【任意】コマンドでのロールバック

自分のターミナルで、`npx wrangler login`（ブラウザで、自分の Cloudflare アカウントにログイン）をしたあと、`npx wrangler rollback` を実行すると、**版を選んで**戻せます（自分のアカウントへのログインが必要です）。

### 6. ずれを直す

`main` の最新（v2）を、**もう一度公開**します。GitHub の **Actions** タブで、直近の **Deploy** の実行を開き、「**Re-run all jobs**」を押します。成功したら、`/health` が、`v2` に戻ることを確認します。

### 7. 考える

- ロールバックは、**問題の根本的な解決**か、**応急処置**か。それは、なぜか。
- **問題のある変更が、本当に、`main` に入ってしまった**場合の、正しい直し方は何か。（M1 で学んだ、安全な戻し方を、思い出す）
- ロールバックで、**戻らない**ものは何か。（README の 6 節）

### 8. 片づけの確認

`/health` が `v2` に戻っていること。`git status` が、きれいであること。
