# M2 AI と学ぶ

所要時間の目安: 準備 30 分 ＋ 説明 20 分 ＋ 演習 70 分

> このモジュールは、M0 の直後に行います。このあとのすべてのモジュールで、AI を使います。先に「AI との付き合い方」を身につけておくと、以降の学びの質が上がります。AI を**統制する**仕組み（許可の設定、worktree など）は、PR とリポジトリの設定を学んだあとの **M6** で扱います。

## 1. このモジュールの狙い

AI は、**答えを出してくれる機械**であると同時に、**何度でも付き合ってくれる先生**にもなります。使い方によって、どちらにもなります。

| 使い方 | 結果 |
|---|---|
| 「答えを書いて」と頼み、出てきたものを写す | 動くものはできるが、**自分は理解していない**。壊れたとき、直せない |
| 「ここが分からない」と**自分の言葉で**伝え、小さく分けて説明してもらい、**自分の言葉で言い直す** | 理解が積み上がる。AI がいなくても、考えられるようになる |

このコースでは、後者を目指します。そのための、3 つの柱があります。

1. **分からないことは、恥じずに「分からない」と言う。まず AI に、自分の言葉で質問する**（M0）
2. **小さな単位まで分けて、1 つずつ理解する**（M0 の 2b）
3. **AI を、安全に使う**（このモジュールと M6）

## 2. AI への指示の基本: チャット画面で、自分の言葉で話しかける

このコースでは、AI（**ローカル AI エージェント**。自分のパソコンの中のファイルを読み、書き、コマンドを実行できる AI）への指示は、**チャット画面に、日本語の普通の文章で書く**ことを基本にします。

- **コマンドや、決まった書き方を覚える必要はありません。** 「〇〇ファイルは、何をしますか」「△△のテストを実行してください」と、人に頼むように書きます。
- AI は、あなたの指示を受けて、**自分で**ファイルを読み、必要ならコマンドを実行しようとします。**そのコマンドの許可を出すのが、あなたの仕事**です（確認画面で、1 つずつ読んでから許可します。本章の 5）。
- 「あなたが入力するコマンド」と「AI が実行しようとするコマンド」は、**別のもの**です。このコースでは、AI に頼むときは、前者ではなく、**自分の言葉の文章**を使います。

## 3. 使う AI エージェント

| | 推奨 | 使ってもよい |
|---|---|---|
| 製品 | **Claude Code** | Codex |
| 理由 | コマンドの実行を、**許可の仕組みで物理的に統制できる**。公式の資料でも、「拒否のルール」は、どの動作モードでも有効と説明されている | 同様の機能を持つ。対応する機能や設定は、M6 の**対応表**で補う |

- **費用は、学生本人の負担**です。有料のプランの契約が必要です（プランと料金は、公式の最新の案内で確認してください）。
- このリポジトリの手順書は、Claude Code を中心に書いています。Codex を使う人は、M6 の対応表を見ながら読み替えます。

### チャット画面を使う方法

Claude Code は、チャット画面のある使い方を、次のように選べます。**どちらか 1 つを選んでください**（どちらも、同じ AI です）。

| 使い方 | 向いている人 | 公式の導入の案内 |
|---|---|---|
| **デスクトップアプリ**（「Code」タブ） | 専用のアプリで、チャットだけに集中したい人 | <https://code.claude.com/docs/en/desktop> |
| **VS Code の拡張機能** | VS Code でコードを見ながら、同じ画面で AI と話したい人。変更の差分が、エディタの画面で見られる | <https://code.claude.com/docs/en/vs-code> |

> ターミナルで使う版（`claude` コマンド）もあり、同じ AI です。ただし、このコースの基本は、**チャット画面**です。ターミナル版の導入は、公式のクイックスタート（<https://code.claude.com/docs/en/quickstart>）にあります。

> 導入の手順は、公式の資料が最新です。**手順書にコマンドや手順を写さず、公式の案内に従ってください。**（確認日: 2026-10-29）

#### 導入のあと、最初にやること

1. アプリ（または VS Code）を起動し、**ログイン**する。
2. **自分のリポジトリのフォルダ**を、AI の作業フォルダに選ぶ。
   - デスクトップアプリ: 「Code」タブで、環境が「Local」になっていることを確認し、プロジェクトのフォルダを選ぶ。
   - VS Code: 自分のリポジトリのフォルダを開き、Claude Code のパネルを開く。
3. チャット欄に、「このフォルダには、何がありますか」のように、**日本語で話しかけて**みる。Enter で送信する。

うまくいかないときは、公式の資料（導入の案内、トラブルシューティング）を見てください。それでも解決しなければ、**「ここまでは分かります、ここから分かりません」の形で、まず AI に（導入そのものが難しければ講師に）**質問してください（M0）。

## 4. AI に読ませてよいもの・いけないもの

| 区分 | 内容 |
|---|---|
| **読ませてよい** | **コード**。開発では、AI にコードを読ませて作業します |
| **絶対に読ませない** | 本番の**個人情報**、各種の **API キー・トークン・パスワード**（秘密） |

- 本番の個人情報や秘密には、そもそも**物理的にアクセスできない形**にします（手元に渡さない）。だから、普通に開発していれば、AI に読ませることはありません。
- 習慣として、**`.env` ファイルも、AI に読ませません**。M7 で作る `.env` には、ローカル環境の（秘密ではない）値しか入りませんが、本物の `.env` を扱うときと同じ習慣にするためです。
- エラーの文などを AI に貼るときは、**秘密や個人情報が入っていないか、貼る前に確認します**。
- 読み取りを**物理的に止める設定**は、M6 で学びます。

## 5. 最初から守る、4 つの統制

AI エージェントは、あなたの代わりに、**ファイルを読み、書き、コマンドを実行**します。ひとつ間違えると、取り返しのつかない操作もできます。最初から、次の 4 つを守ってください。

1. **AI が実行しようとするコマンドを、1 つずつ読んでから許可する。** 内容が分からないコマンドは、許可しない（チャットで「このコマンドは、何をするのですか」と聞く）。
2. **最初は、読むだけ・提案させるだけにする。** 変更させる前に、「何をするつもりか」を説明させる。
3. **変更されたら、必ず差分を読む。** 画面の差分表示と、`git status`・`git diff` で、何が変わったかを自分の目で確かめる。
4. **秘密・個人情報・`.env` を渡さない。**

### 動作モード

Claude Code には、「どこまで確認なしで実行するか」を決める、**動作モード**があります。チャット画面の、**プロンプト欄（入力欄）の近く**にあるモードの選択欄（またはモード表示）で切り替えます。

| モード | 確認なしで実行されること | このコースでの扱い |
|---|---|---|
| **Manual** | 読み取りだけ。ファイルの変更やコマンドの実行は、毎回確認される | **使う**。基本のモード |
| **Plan** | 読み取りだけ。変更は、計画を承認するまでできない | **使う**。最初の「読むだけ」に最適 |
| **Accept edits**（VS Code・ターミナルでは **Edit automatically**） | 読み取りと、作業フォルダの中のファイル編集 | M6 で学んだあと、**範囲が限られているとき**（worktree の中など）に使ってよい |
| **Auto** | ほぼすべて（裏で、AI が行動を審査） | **このコースでは使わない**（仕組みは M6 で学ぶ） |
| **Bypass permissions** | **すべて**。隔離した環境専用 | **使わない** |
| （ターミナルのみ）**Don't ask** | 許可済みのものだけ。それ以外は拒否 | このコースでは扱わない |

#### 切り替え方（公式の資料で確認した内容。確認日: 2026-10-29）

| 使い方 | モードの切り替え |
|---|---|
| デスクトップアプリ | プロンプト欄の下の、**モードの選択欄**。Windows では、Ctrl+Shift+M でモードのメニューが開く |
| VS Code 拡張 | プロンプト欄の下の、**モードの表示**をクリック |
| ターミナル | Shift+Tab で切り替え。起動時に指定する方法もある |

> **重要**: 使い方や**バージョンによって、起動した時点のモードが違います**。VS Code 拡張の新しい版では、**最初のモードが Auto** です。**会話を始める前に、必ず、画面のモード表示を見て、Manual か Plan になっていることを確認してください。** 違っていたら、切り替えます。
>
> モードの名前や挙動は、バージョンで変わることがあります。**公式の最新の資料**（<https://code.claude.com/docs/en/permission-modes>）も、ときどき見てください。

## 6. AI と学ぶときの型

### 小さく分けて、理解する

M0 の 2b の手順を、AI と一緒に行うと、次のようになります。

| 手順 | やること | AI の役割 |
|---|---|---|
| 1 | **自分の力で**、まず読む・考える。「ここまでは分かる」を言葉にする | なし（まだ使わない） |
| 2 | 「ここから分からない」を、**いちばん小さな 1 点**にする | なし |
| 3 | その 1 点だけを、チャットで、**自分の言葉で**質問する | 説明する |
| 4 | **自分の言葉で、言い直す** | 聞き役 |
| 5 | 「間違っているところを指摘して」と頼む | 添削する |
| 6 | 自分でやってみる。**確かめる**（実行する、テストする） | — |

### 質問の型（チャットに書く文章）

| 悪い質問 | 良い質問 |
|---|---|
| 「これを説明して」（広すぎる） | 「この 3 行目の `>` は、何と何を比べていますか」 |
| 「直して」（丸投げ） | 「この関数が、〇〇のとき ×× になる理由を、1 つずつ教えてください」 |
| 「テストを書いて」 | 「この関数の、間違いやすい入力を、3 つ挙げてください。まず、テストは書かないでください」 |

### 「分からない」の言い方

> 「**ここまでは分かります。ここから分かりません。**」

この一文を、AI にも、人にも使ってください。**分からない場所を、自分の言葉で言える人は、いちばん早く伸びます。**

### AI の答えは、確かめる

AI は、**もっともらしい、間違い**を言うことがあります。分かった気になる前に、次のように確かめます。

- 実際に実行する、テストを走らせる
- コードを読んで、書かれていることと照らし合わせる
- 「コードに書かれていないこと」を聞かれたとき、AI が**「分からない」と言えているか**を見る（演習 3）

## 7. AI を使うときの約束

1. **差分を読んでから出す。** AI が変更したファイルと行を、すべて自分の目で確認する。意味が説明できない変更は、出さない。
2. **範囲を決めて頼む。** 「このファイルの、この部分だけ」と指定する。範囲の外が変わっていたら、取り消す。
3. **秘密・個人情報・本番のデータを、AI に渡さない。**
4. **「動いた」と「安全」は別。** 特に、認証・権限・個人情報に関わる部分は、人が丁寧に読む。
5. **テストを通すために、テストを弱めない。** テストを消す、`skip` にする、期待値を書き換える、は禁止。
6. **勝手に依存を足さない。** 新しいライブラリは、必要性を説明できてから。
7. **Issue は AI が自律的に作らない。** 起票案を出してもらい、人が決める。
8. **分からないまま進めない。** AI の説明が理解できないときは、聞き直すか、人に聞く。

### よくある失敗

| 失敗 | 起きること | 見つけ方 |
|---|---|---|
| 範囲外のファイルまで書き換える | レビューが難しくなる。意図しない動作変更 | 変更ファイルの一覧を見る（M4-3 で練習） |
| 存在しない関数・設定を使う | 動かない、または動いたように見える | 実行して確認する、公式の資料で確かめる |
| テストを通すために緩める | 問題が隠れる | テストの変更を、特に注意して読む |
| 秘密に見える値を埋め込む | 漏えい | CI の `secret-scan`、目視 |
| 「念のため」の余計な処理を足す | 複雑になる、保守できなくなる | 「なぜ必要か」を説明させる |
| **分かったふりをして進む** | 後で、自分で直せなくなる | 自分の言葉で言い直せるか、確かめる |

## 9. 確認（面談）

- AI を「答えを写す道具」でなく、「先生」として使うとは、どういうことか。
- AI への指示は、どのように書くのが基本か。「あなたが入力するコマンド」と「AI が実行しようとするコマンド」は、どう違うか。
- AI が実行しようとするコマンドを、読んでから許可する理由は。
- このコースで使わないモードは何か。それはなぜか。会話を始める前に、何を確認するか。
- 分からないことを、「ここまでは分かる、ここから分からない」の形で、自分の言葉で 1 つ説明してみよう。
- AI の説明を、鵜呑みにしないために、何をするか。
