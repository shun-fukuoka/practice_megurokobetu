# M2-1 の答えと解説

> 先に、自分の予想と考えを書き残してから読んでください。AI の出力は、毎回少しずつ違います。ここに書くのは「典型的な様子」と「考え方」です。

## 設問: 読むだけか、変更するか

### ヒント

- Plan モードは、「変更は、計画を承認するまでできない」モード。
- ファイルを**読む**ことと、コマンドを**実行する**ことは、別の操作。

### 答え

- 「このファイルは何をしますか」への答えは、**ファイルを読むだけ**で行われる。変更はされない。読むだけの操作は、確認なしで実行されることが多い（公式の資料でも、Manual と Plan では「読み取り」は確認なしと説明されている）。
- 「テストを実行して」は、**コマンドの実行**なので、確認画面が出ることが多い。確認画面には、実行されようとしているコマンド（例: `npm run test` や、フォルダを移動してから実行する形）が書かれている。

## 手順 4: 確認画面の読み方

### 4 つの区分

| 区分 | 例 | 許可の考え方 |
|---|---|---|
| **読むだけ** | ファイルの一覧・内容の表示、`git status`、`git log` | 内容が分かれば、許可してよい |
| **ファイルを変更する** | ファイルの書き込み、`npm install`、`git commit` | **何を変えるかを、確かめてから**。範囲が頼んだ内容と合っているか |
| **外部に何かを送る** | `git push`、`curl`、メールや投稿 | **慎重に**。送る内容と、送り先を確かめる。M2 の段階では、許可しない |
| **消す** | `rm`、ブランチの削除、`git reset --hard` | **原則、許可しない**。取り消せないことが多い |

### この演習のコマンドの例

テストの実行（例: `cd modules/m4-pr-and-ci/app && npm run test`）は、次のように読めます。

- **何をするか**: `app` フォルダに移動し、型の検査・コンパイルを行って、テストを実行する。
- **区分**: 主に「読むだけ」に近いが、`dist/` というフォルダにコンパイル結果を**書き込む**（ファイルを作る）。`dist/` は、Git の対象外になっている。
- **判断**: 内容が分かり、頼んだとおりなので、**許可してよい**。

### 内容が分からないコマンドが出たら

**許可しません。** 次の順で進めます。

1. AI に、「このコマンドは、何をしますか。1 つずつ区切って教えてください」と聞く。
2. それでも分からなければ、講師に、「**このコマンドが分かりません**」と伝える。
3. 分かるまで、許可しない。

「分からないので許可しない」は、**正しい判断**です。

## 手順 5: 変更を頼んだとき

Plan モードでは、ファイルは**変更されず**、まず「何を、どう変えるか」の**計画**が示されます。計画を承認しなければ、変更は行われません。`git status` が空のままであることが、それを裏づけます。

> 注意: 公式の資料には、条件によっては、Plan モードの制限が効かない場合があるという注意書きがあります（例: 確認を省く強いモードが有効になっている場合）。**そのため、動作モードの表示を、自分の目で確認する**習慣が大切です。

## 振り返りの答え

- **確認画面を読む理由**: AI は、あなたの代わりに、ファイルを変更し、コマンドを実行できる。許可は、**あなたが責任を持つ操作**。読まずに許可すると、意図しない変更や削除、外部への送信が、起こりうる。
- **分からないコマンドが出たとき**: 許可せず、AI や講師に聞く。分からないまま進めない。
- **Plan モードで変更を頼んだとき**: 変更はされず、計画が示された。承認しなければ、ファイルは変わらない。
