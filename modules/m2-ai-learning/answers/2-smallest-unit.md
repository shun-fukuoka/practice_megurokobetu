# M2-2 の答えと解説

> 先に、自分の考えを書き残してから読んでください。AI とのやり取りは、毎回変わります。ここに書くのは、「分け方の例」と「考え方」です。

## 手順 0: この 1 行は、何をしているか

```ts
if (now - session.loginAt > policy.absoluteMs) {
```

### ヒント

1. 行を、記号ごとに区切る: `now` / `-` / `session.loginAt` / `>` / `policy.absoluteMs`
2. 「A - B」と「A > B」は、別の操作。まず引き算、次に比較。
3. `loginAt` は「ログインした時刻」、`now` は「今の時刻」。

### 分け方の例

| 部分 | 意味 |
|---|---|
| `now` | 今の時刻（ミリ秒）。引数で受け取る |
| `session.loginAt` | ログインした時刻（ミリ秒） |
| `now - session.loginAt` | **ログインしてから、何ミリ秒たったか** |
| `policy.absoluteMs` | ログインから許される、最大の時間（ミリ秒） |
| `>` | 左が、右より**大きい**（超えている）か。ちょうど等しいときは、含まない |

### 全体の言い直しの例

> 「ログインしてから、許された最大の時間を**超えた**ら、セッションは無効にする、という条件。」

## 手順 1〜3: AI に聞くときの、良い例・悪い例

| | 例 | 評価 |
|---|---|---|
| 良い | 「`now - session.loginAt` は、何を計算していますか。この部分だけ」 | 1 点に絞れている。答えを確かめやすい |
| 良い | 「私の理解は『…』です。間違いを指摘してください」 | 自分の言葉で言い直し、**添削**を頼んでいる |
| 悪い | 「この関数を全部説明して」 | 一度に多すぎて、どこが分からないかが、ぼやける |
| 悪い | 「この条件を直して」 | 理解せずに、丸投げ |

## 手順 4: 記録の書き方の例

> **分かったこと**: ログインしてから、許された時間を超えたら、無効にする条件。`>` は「超えた」で、ちょうど等しいときは含まない。
> **まだ分からないこと**: ここまでは分かる。ここから、`policy` が、どこで決まっているかが分からない（呼び出し側のコードを、まだ読んでいない）。
> **役に立った質問**: 「`now - session.loginAt` は何を計算していますか」（1 点に絞れた）
> **役に立たなかった質問**: 「全体を説明して」（長すぎて、どこが分からないか分からなくなった）

## 振り返りの答え

- **最初に自分で考えてから AI に聞く違い**: 自分の**分かる範囲と、分からない範囲**が、はっきりする。そのため、**聞く質問が小さく、的確**になる。最初から聞くと、AI の説明を「分かった気」になるだけで、自分がどこまで分かっていたかが、分からなくなる。
- **自分の言葉で言い直す理由**: 言い直せないところが、**本当に分かっていない場所**。AI の文章を読んで頷いても、言い直せなければ、理解していない。
- **まだ分からないことが残ったとき**: 次の 1 点を、さらに小さく分けて、同じ手順を繰り返す。それでも分からなければ、「ここまでは分かる。ここから分からない」の形で、講師に聞く。
