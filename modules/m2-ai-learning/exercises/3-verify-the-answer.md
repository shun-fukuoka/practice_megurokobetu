# 演習 M2-3: AI の説明を確かめる

所要時間の目安: 20 分 / 前提: [演習 2](2-smallest-unit.md)

## 目的

- AI の説明を、**実際に確かめる**習慣をつける。
- AI が、**コードに書かれていないこと**を聞かれたとき、どう答えるかを観察する。

## 手順

### 0. 記録の Issue を作り、予想を書く（AI を使わずに）

[演習の進め方（M0 の 3b）](../../m0-orientation/README.md)に従い、「演習の記録」の Issue（演習: `M2-3`）を作ります。次の予想を、**AI を使う前に、自分の力で**書いてください。

- `modules/m4-pr-and-ci/app/src/session-policy.ts` の `evaluateSession` で、「操作がないまま、ちょうど idle の上限の時間がたったとき」は、有効か無効か。（コードを、自分で読んで考える）
- AI に「このアプリの、**本番環境の**セッションの有効時間は、何分ですか」と聞いたら、AI はどう答えると思うか。

### 1. 始める前の状態を確かめる

自分のターミナルで、次を実行します。

```bash
git status
```

変更が出ないことを確認します。

### 2. AI に、確かめられる質問をする

AI のチャット画面を開き（モードは Manual か Plan。画面のモード表示を確かめる）、チャット欄に、次のように入力して送信します。

> 「`session-policy.ts` の `evaluateSession` で、『最後に操作してから、ちょうど `idleMs` ミリ秒がたった』ときは、有効ですか。無効ですか。コードのどの部分から、そう言えるのか、教えてください。」

AI の答えと、その**根拠として示された行**を読みます。

### 3. 実際に確かめる

AI の答えを、**鵜呑みにせず**、次のどちらかで確かめます。

- **コードで確かめる**: 示された行を、自分で読む。`>` と `>=` の、どちらが書かれているか。
- **実行して確かめる**: `modules/m4-pr-and-ci/app/src/session-policy.test.ts` の、**いちばん下**に、次のテストを一時的に足す。そして、自分のターミナルで、テストを実行する。

  ```ts
  test("ちょうど idle の上限のときは、有効（確認用・一時的）", () => {
    const status = evaluateSession({ loginAt: t0, lastActiveAt: t0 }, t0 + 1 * HOUR, policy);
    assert.deepEqual(status, { valid: true });
  });
  ```

  ```bash
  cd modules/m4-pr-and-ci/app
  npm run test
  ```

  > テストの実行は、AI にチャットで頼んでも構いません（「`modules/m4-pr-and-ci/app` のテストを実行してください」）。その場合は、確認画面を読んでから許可します。

AI の答えは、合っていましたか。予想（手順 0）とは、どうでしたか。

### 4. コードに書かれていないことを聞く

AI のチャット欄に、次のように入力して送信します。

> 「このアプリの、本番環境の、セッションの有効時間は、何分ですか。」

AI の答えを読み、次を記録の Issue のコメントに書きます。

- AI は、「分からない」と言えたか。それとも、**もっともらしい数字や説明を言った**か。
- もし、数字を言った場合、その根拠は、どこにあると言っているか。そのファイルは、実際にあるか。

### 5. 片づけ

手順 3 で足したテストを**削除**し、チャットを閉じます。

**片づけの確認**: 自分のターミナルで、リポジトリのルートから、次を実行します。

```bash
git status
```

**何も表示されない**こと。

## 振り返り

- AI の説明を確かめる方法を、2 つ挙げられるか。
- AI が、分からないことを「分からない」と言えるのは、なぜ大切か。人にも同じことが言えるか。

答えは [answers/3-verify-the-answer.md](../answers/3-verify-the-answer.md)。見たあと、記録の Issue に「答えを見て気づいたこと」をコメントし、Issue を閉じます。
