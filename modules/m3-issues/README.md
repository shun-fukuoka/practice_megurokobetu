# M3 Issue と Discussions

所要時間の目安: 45 分（説明 15 分 ＋ 演習 30 分）

## 1. Issue とは

**1つの作業の単位を、記録する場所**です。「何を、なぜ、どうなったら終わりか」を書きます。

Issue が無いと、次のことが起こります。

- 何のための変更か、後から分からなくなる
- 「終わり」の基準がなく、レビューも「なんとなく」になる
- 同じ作業を、二人が別々に始めてしまう

## 2. 良い Issue の条件

| 項目 | 内容 |
|---|---|
| **背景** | 誰が、何に困っているか。「〜したい」だけでなく、なぜか |
| **完了条件** | 第三者が「終わった」と判断できる書き方。箇条書きで、確認できる形に |
| **範囲** | 今回やらないこと。ここに書くと、レビューで「ついでの変更」を見つけやすい |
| **大きさ** | PR 1本で終わる大きさ。大きすぎるときは、分ける |

### 悪い例と良い例

**悪い例**

> タイトル: ボタンを直す
> 本文: ボタンの見た目がおかしいので直してください

何がおかしいのか、どうなれば直ったのか、分かりません。

**良い例**

> タイトル: 保存ボタンが、スマートフォンの幅で画面からはみ出す
> **背景**: 幅 375px の画面で、保存ボタンの右端が切れて押しにくい
> **完了条件**
> - [ ] 幅 375px で、ボタン全体が画面内に収まる
> - [ ] 幅 1280px の見た目は変わらない
> **範囲**: ボタンの色・文言は変えない

## 3. Discussions とは

**まだ「作業」になっていないこと**を話す場所です。

| 使うもの | 向いていること |
|---|---|
| **Issue** | やることが決まっている。完了条件が書ける |
| **Discussions** | 質問、相談、方針の検討、「やるべきか」の議論 |

迷ったら Discussions に書き、**やることが決まったら Issue にする**、で問題ありません。

> ※ 自分のリポジトリで Discussions を使うには、Settings → General の「Features」で有効にします（M5 で触れます）。

## 4. AI と Issue

AI が自分で判断して Issue を作ることは、しません。必要だと思ったら、AI に**起票案（題名・背景・完了条件）**を出してもらい、人が読んで、起票するかを決めます。
