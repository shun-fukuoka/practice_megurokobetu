# 演習 M3: Issue を書く

所要時間の目安: 30 分 / 前提: [README](README.md)

## 目的

「困りごと」を、他の人が作業できる形（背景・完了条件・範囲）に書き直せるようになる。

## 手順

### 0. 先に、自分の考えを書き残す

[演習の進め方（M0 の 3b）](../m0-orientation/README.md)に従い、「演習の記録」の Issue（演習: `M3`）を作ります。この演習は予想ではなく、**設問 1・2 の自分の下書き**を、その Issue の本文（予想の欄）に書いてください。答えを見る前に書くことが大切です。

### 1. 悪い Issue を直す（10 分）

次の依頼を、Issue フォーム（`Issues` → `New issue` → `作業（Task）`）に沿って書き直してください。**実際に起票せず、メモ帳に下書き**してかまいません。

> 「セッションの期限切れの判定、なんか分かりにくいから直しておいて」

書き直すとき、次を決めてください。

- 何が「分かりにくい」のか（あなたが推測して、仮定として書く）
- 完了条件を、**第三者が確認できる形**で3つ以内
- 今回やらないこと

### 2. 自分の Issue を書く（15 分）

`modules/m4-pr-and-ci/app/src/session-policy.ts` を読んで、**改善案を1つ**考え、自分のリポジトリの Issue として起票してください。例:

- テストが足りないケースの追加
- エラーの理由（`reason`）を分かりやすくする
- 型や名前の見直し

起票したら、講師に URL を共有してください（共有の方法は M5 で学びます。それまでは、画面のスクリーンショットでかまいません）。

### 3. 振り返り（5 分）

- 書いている途中で、「これは決まっていない」と気づいた点はあったか。
- 完了条件に、「いい感じに」「適切に」のような曖昧な言葉が入っていないか。

## 確認

- [ ] 背景は、「誰が」「何に」困っているかを書いた
- [ ] 完了条件は、第三者が○×を付けられる
- [ ] 範囲（やらないこと）を1つ以上書いた
- [ ] PR 1本で終わる大きさである

答えは [answers.md](answers.md)。
