# 演習 M4-2: 秘密を混入させる

所要時間の目安: 25 分 / 前提: [M0](../../m0-orientation/README.md) の「秘密」

## 目的

- 秘密の混入を、CI が検出する様子を見る。
- **ファイルを消しても、履歴には残る**ことを理解する。

## 重要

- この演習で使うのは、スクリプトが**その場で生成する偽の値**です。本物の秘密は使いません。
- 偽の値は、リポジトリの中にあらかじめ置いていません。置くと、本物の検出器に拾われるためです。

## 手順

### 0. 記録の Issue を作る

[演習の進め方（M0 の 3b）](../../m0-orientation/README.md)に従い、「演習の記録」の Issue（演習: `M4-2`）を作ります。手順 5 の予想は、**実行する前に**、この Issue に書いてください。

### 1. ブランチを作る

```bash
git switch main
git pull
git switch -c practice/secret-trap
```

### 2. 偽の秘密を作る（リポジトリのルートで実行）

```bash
node modules/m4-pr-and-ci/tools/make-fake-token.mjs
```

`notes/leak-demo.txt` に、GitHub のトークンに似せた偽の文字列が書き込まれます。**中身を確認してください**（何かの設定ファイルに見えますか？）。

### 3. コミットして PR を出す

```bash
git add notes/leak-demo.txt
git commit -m "practice: 秘密の混入を体験する"
git push -u origin practice/secret-trap
```

`main` 宛ての PR を出し、`secret-scan` ジョブが**赤くなる**ことを確認します。

### 4. ログを読む

- どのファイル・どのコミットで検出されたか。
- ログに、値そのものが表示されているか（`--redact` により伏せられている点に注目）。

### 5. 「消せば安全」か確かめる（その前に予想を書く）

先に、**結果を予想して、記録の Issue に書いて**ください。そのあと実行します。

```bash
git rm notes/leak-demo.txt
git commit -m "practice: 秘密のファイルを削除する"
git push
```

CI が再実行されます。

- `secret-scan` は緑に戻るか、赤のままか。
- それはなぜか。

### 6. 実際の現場なら、何をするか（考える）

本物の秘密をコミットしてしまった場合、最初に何をするべきか、**順番とその理由**を書いてください。

### 7. 片づけ

PR は**マージせずにクローズ**し、ブランチを削除します。
