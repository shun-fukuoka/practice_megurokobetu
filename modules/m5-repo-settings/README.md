# M5 リポジトリの設定（オーナーとして）

所要時間の目安: 90 分（説明 20 分 ＋ 演習 70 分）

## このモジュールの狙い

自分のリポジトリでは、あなたが**オーナー**です。設定画面を自由に触れます。このモジュールでは、オーナーだからできることを実際に体験し、**チームの一員として開発するときとの違い**を理解します。

> 実際の開発（本番のシステム）では、あなたはオーナーではなく、書き込み権限（Write）を持つ**メンバー**になります。秘密や設定には触れません。この違いを、体験で理解することがゴールです。

## 1. Secrets と Variables

自動化（CI）が使う「設定の値」を、リポジトリに登録できます。登録場所は、Settings → Secrets and variables → Actions です。

| | Variables（変数） | Secrets（秘密） |
|---|---|---|
| 用途 | 秘密でない設定値（例: 表示名、環境の名前） | 秘密の値（例: API のトークン） |
| 登録後に値を見られるか | **見られる** | **見られない**（更新はできる） |
| ログへの出力 | そのまま出る | 自動で `***` に置き換わる（マスク） |
| 誰が使えるか | このリポジトリのワークフロー | 同左（ただし、外部からのフォークの PR には渡されない） |

**秘密をコードや `.env` に直接書かず、Secrets に登録する**のが基本です。コードは多くの人が読めますが、Secrets は読み出せないからです。

### 注意: マスクは万能ではない

ログの `***` への置き換えは、「値がそのまま出力されたとき」を隠すだけです。値を加工して出力すると（逆順にする、1文字ずつ分ける等）、隠れません。**秘密をログに出さない**ことが、本当の対策です。

## 2. コラボレーターと権限

自分のリポジトリに、他の人を招待できます。招待するとき、権限（ロール）を選びます。

| 権限 | できること（概略） |
|---|---|
| **Read** | 読む、クローンする、Issue・PR にコメントする |
| **Write** | 上に加えて、ブランチに push する、PR をマージする |
| **Admin** | 上に加えて、設定の変更、Secrets の登録、コラボレーターの管理、リポジトリの削除 |

**最小権限の原則**: 必要な作業ができる、最小の権限だけを渡します。「念のため Admin」にしません。

### 権限は、外すところまでが仕事

メンバーが抜けたら、**権限を外します**。外し忘れは、使われない鍵を放置するのと同じで、後で事故の原因になります。

## 3. 実際の開発との違い

| | 自分のリポジトリ（練習） | 実際の開発 |
|---|---|---|
| あなたの権限 | オーナー（Admin） | Write |
| main への直接 push | できてしまう（自分で守る） | 設定で止められる |
| Secrets | 自分で登録・管理 | **見られない・触れない**。CI だけが持つ |
| 設定の変更 | 自由 | 管理者のみ |
