# M5-2 の答えと解説

> 先に、自分の予想と考えを書き残してから読んでください。

## 設問0・4・5: 権限の違い

### ヒント

- 「読む」「書く」「設定を変える」は、別の権限。
- 設定や Secrets は、**リポジトリの管理者（Admin）だけ**の領域。

### 答え

| できること | Read | Write | Admin（オーナー） |
|---|---|---|---|
| クローンして読む | ○ | ○ | ○ |
| Issue・PR にコメントする | ○ | ○ | ○ |
| ブランチに push する | × | ○ | ○ |
| PR をマージする | × | ○ | ○ |
| Settings・Secrets を見る／変える | × | × | ○ |
| コラボレーターを管理する | × | × | ○ |

- **B（Write）は**、ブランチを作って push し、PR を出せる。Settings タブは**見えない**。Secrets を見られず、他の人も招待できない。
- **Read に変えると**、B の push は**拒否される**。クローンして読むことと、コメントだけができる。

## 設問3: レビュー

- **コメント**: 疑問や提案を、特定の行に付ける。
- **Request changes**: 修正が必要であることを、正式に伝える。
- **Approve**: 問題なしと承認する。

自分の PR は自分で承認しても意味がない（作者以外の目が、レビューの価値）。この演習では、**相手の目で見てもらう**ことが目的。

> 注意: このリポジトリ（練習用）には、保護の設定がないので、Approve がなくてもマージはできてしまう。実際の開発では、Approve を必須にする設定で、これを強制する。

## 設問6: 権限を外す

外すと、B はクローンも push もできなくなる（すでに手元にあるコピーは残る点に注意。これが、コードを扱う人との秘密保持契約が必要な理由の一つ）。

## 振り返りの答え

- **Write と Admin の違い**: Write は「コードを書いて出す」まで。Admin は「リポジトリの設定・秘密・人の管理」まで。
- **実際の開発では**: あなたは**メンバー（Write）**。理由は、最小権限の原則と、**秘密を開発者に渡さない**方針による。設定や秘密は、管理者と CI が持つ。
- **レビューで指摘されたこと**があれば、それは「自分の目では見えていなかった」ことの実例。PR の作者がすべての行を説明できるべき、という原則とつながる。
