# 演習 M5-2: コラボレーターとレビュー

所要時間の目安: 40 分 / 前提: [README](../README.md)、[M4](../../m4-pr-and-ci/README.md)

## 目的

- 他の人を招待して、**権限の違い**を体験する。
- 自分の PR を**他の人にレビューしてもらう**流れを体験する。
- 権限を**外す**ところまでを、1つの作業として完了させる。

## 準備

2人1組で行います（相手が決まらないときは、講師が相手になります）。ここでは、一人を **A**、もう一人を **B** とします。互いに、相手のリポジトリを使う回を1回ずつ行ってください。

## 手順（A のリポジトリを使う回）

### 0. 先に予想を書く

[演習の進め方（M0 の 3b）](../../m0-orientation/README.md)に従い、「演習の記録」の Issue（演習: `M5-2`）を作り、次の予想を、**実行前に**その Issue に書いてください（A・B それぞれ、自分のリポジトリに）。

- B に **Write** を渡したとき、B は何ができて、何ができないか。
- B に **Read** に変えたとき、何が変わるか。

### 1. A: B を Write で招待する

Settings → Collaborators → Add people。B の GitHub のユーザー名で招待し、権限を **Write** にします（招待を B が承認する必要があります）。

### 2. B: ブランチを作って、PR を出す

B は A のリポジトリをクローンし、ブランチを作って、README に1行（自己紹介など）を足し、`main` 宛ての PR を出します。PR テンプレートを埋めてください。

### 3. A: レビューする

A は PR を開き、「Files changed」で変更を読みます。次の3つを試してください。

- 1行に**コメント**をつける
- 「Request changes」で、修正を依頼する
- 修正後に、「Approve」する

### 4. B: できないことを確かめる

B は、A のリポジトリで次を試します（見えない・できないことを、確認してください）。

- Settings タブは見えるか。Secrets を見られるか。
- 他のコラボレーターを招待できるか。

### 5. A: 権限を Read に変える

A は B の権限を **Read** に変えます。B は、同じブランチに push してみます。何が起きますか。

### 6. A: B を外す（片づけ）

A は B をコラボレーターから**削除**します。B が、リポジトリにアクセスできなくなったことを、B に確認してもらいます。

### 7. 役割を交代して繰り返す

A と B を入れ替えて、手順 1〜6 をもう一度行います。

## 振り返り

- Write と Admin で、できることがどう違ったか。
- レビューで、自分が気づけなかった点を相手に指摘されたか。
- 実際の開発では、あなたはどちらの立場（オーナー／メンバー）か。それはなぜか。
