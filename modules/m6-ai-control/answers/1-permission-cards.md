# M6-1 の答えと解説

> 先に、自分の判断と理由を書き残してから読んでください。**答えは、状況によって変わる部分があります。** 大切なのは、結論そのものより、**理由が、観点で説明できる**ことです。

## 12 枚の、判断の例

| # | コマンド | 区分 | 判断の例 | 理由（観点） |
|---|---|---|---|---|
| 1 | `git status` | 読むだけ | **許可** | 何も変更しない。取り消す必要がない。何をするか分かる |
| 2 | `npm run test` | 読むだけに近い | **確かめてから許可** | 頼んだ内容と合っている。**どのフォルダで実行するか**を確かめる。`dist/` を作る（Git の対象外） |
| 3 | `cat .../app/.env` | 秘密に触れる | **拒否** | `.env` は、AI に読ませない（M0・M2）。ローカルの値でも、**習慣**。原因調べは、`.env.example` と、自分の目で確かめた設定から行う |
| 4 | `rm -rf node_modules` | 消す | **確かめてから許可** | 頼んだ内容と合っている。作業フォルダの中で、**再び作れる**（`npm ci`）。ただし、**どのフォルダの** `node_modules` かを確かめる（`rm -rf` の対象が、広すぎないか）。頼んでいなければ、拒否 |
| 5 | `git push --force origin main` | 外へ出る・消す | **拒否** | **取り消せない**（他の人の履歴を上書きする）。外へ出る。`main` への直接 push は、そもそもしない（M4）。AI の提案でも、許可しない |
| 6 | `git commit -m "..."` | 変更する | **確かめてから許可** | 頼んだ内容と合っているが、**差分をまだ読んでいない**。**先に `git diff` で、何が含まれるかを確かめる**。秘密や、範囲外の変更が混ざっていないか |
| 7 | `npm install left-pad-ultra` | 変更する（依存の追加） | **拒否** | **見知らぬライブラリ**は、危険（M2 の約束 6）。必要性を、説明できるまで入れない。頼んでいない変更 |
| 8 | `curl ... \| bash` | 外から取り込んで実行 | **拒否** | **出所の分からないスクリプトを、そのまま実行する**。中身を確かめられない。取り消せない |
| 9 | `git reset --hard HEAD~3` | 消す | **拒否** | 未コミットの変更と、直前の 3 コミットを**失う**。取り消しにくい。**まず `git log` と `git status` で、何が失われるかを確かめる**。別の方法（`git revert` など）を、相談する |
| 10 | `ls modules` | 読むだけ | **許可** | 何も変更しない |
| 11 | `git branch -D old-feature` | 消す | **確かめてから許可（または拒否）** | 頼んだが、`-D` は**強制削除**（マージされていなくても消す）。**そのブランチに、残したい作業がないか**を、確かめてから。確かめられなければ、拒否 |
| 12 | `docker system prune -a` | 消す（範囲が広い） | **拒否** | **使っていないイメージ・コンテナを、すべて**消す。**他のプロジェクトの環境**にも、影響する（時間のかかる取得のやり直しになる）。頼んだ範囲を超えている |

## 考えるときの、観点

| 観点 | 問い | 該当するカード |
|---|---|---|
| **取り消せるか** | 失敗したら、元に戻せるか | 5, 9, 11, 12 |
| **範囲** | 影響が、頼んだ範囲を超えないか | 4, 12 |
| **外へ出るか** | 外部に送る、外から取り込むか | 5, 8 |
| **秘密に触れるか** | `.env`、鍵、個人情報か | 3 |
| **分かるか** | 何をするか、説明できるか | すべて |

## 設問への答え

- **「あなたが頼んだ」カードでも、拒否や、確かめてから許可になる**: 頼んだことと、**実際に実行されるコマンドの範囲が、一致しているとは限らない**から（4: 対象フォルダ、6: 含まれる差分、11: 強制削除）。**頼んだ＝何でも許可、ではない。**
- **「頼んでもいないのに、AI が提案した」カード**: AI が、**自分で判断して、危険な方法を選んだ**可能性がある（3, 5, 8, 9, 12）。なぜその方法が必要なのか、**理由を聞く**。別の安全な方法がないかを、聞く。
- **迷ったときの倒し方**: **拒否する側**（止まる側）。許可して失うものは、取り返せないことが多い。拒否して失うのは、時間だけ。拒否してから、AI に「安全な別の方法」を、相談すればよい。

## 振り返りの答え

- 人によって、よく使う観点は違う。「取り消せるか」と「分かるか」は、ほとんどのカードで使える、基本の観点。
- **「分からないから許可しない」は、正しい判断**。分からないまま許可するほうが、はるかに危険。分からないコマンドは、AI に説明を聞き（実行はさせない）、理解してから、判断し直す。
