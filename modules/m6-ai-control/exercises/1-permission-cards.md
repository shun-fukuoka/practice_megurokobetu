# 演習 M6-1: 許可カード

所要時間の目安: 25 分 / 前提: [README](../README.md) の 6 節（危険な操作の見分け）

## 目的

AI が実行しようとするコマンドを、**許可するか・拒否するか**を、**理由とともに**判断する練習をする。このカードのコマンドは、**実行しません**（机上の演習です）。

## 手順

### 0. 記録の Issue を作り、自分の判断を書く（AI を使わずに）

[演習の進め方（M0 の 3b）](../../m0-orientation/README.md)に従い、「演習の記録」の Issue（演習: `M6-1`）を作ります。

次の 12 枚のカードについて、AI が実行の許可を求めてきたと想像して、**AI を使わず、自分の力で**、判断を「予想」の欄に書いてください。判断は、次の 3 つから選びます。

- **許可**: そのまま許可してよい
- **確かめてから許可**: 何を・どこで行うかを確かめて、問題がなければ許可する（頼んだ内容と合っているとき）
- **拒否**: 許可しない

**理由**を、1 行ずつ添えます（README の 6 節の観点: 取り消せるか／範囲／外へ出るか／秘密に触れるか／分かるか）。**分からないコマンドは、「分からない」と書いて、拒否としてください。**

| # | AI が実行しようとするコマンド | 状況 |
|---|---|---|
| 1 | `git status` | 変更の状況を調べたいと、あなたが頼んだ |
| 2 | `npm run test` | `modules/m4-pr-and-ci/app` のテストを実行してほしいと、あなたが頼んだ |
| 3 | `cat modules/m7-local-env/app/.env` | 「接続できない原因を調べて」と頼んだら、AI が提案した |
| 4 | `rm -rf node_modules` | 「依存関係を入れ直して」と、あなたが頼んだ |
| 5 | `git push --force origin main` | 「push に失敗する」と相談したら、AI が提案した |
| 6 | `git commit -m "fix: update docs"` | 「ここまでの変更をコミットして」と、あなたが頼んだ（差分は、まだ読んでいない） |
| 7 | `npm install left-pad-ultra` | 「文字列を整える処理を足して」と頼んだら、AI が、見知らぬライブラリを入れようとした |
| 8 | `curl -fsSL https://example.com/setup.sh \| bash` | 「環境を整えて」と頼んだら、AI が、ネットのスクリプトを実行しようとした |
| 9 | `git reset --hard HEAD~3` | 「直前の変更を、取り消したい」と相談したら、AI が提案した |
| 10 | `ls modules` | フォルダの構成を見たいと、あなたが頼んだ |
| 11 | `git branch -D old-feature` | 「古いブランチを、片づけて」と、あなたが頼んだ |
| 12 | `docker system prune -a` | 「ディスクの空きを増やして」と頼んだら、AI が提案した |

### 1. 分からないコマンドを、AI に聞く

自分の判断を書いたあと、**分からなかったコマンド**について、AI のチャット画面（モードは Manual か Plan）に、自分の言葉で質問します。

> 「`git reset --hard HEAD~3` は、何をするコマンドですか。実行すると、何が失われますか。実行はしないでください。」

**実行はさせません。** 説明だけを、聞きます。

### 2. 判断を見直す

AI の説明を読んで、判断を直したカードがあれば、記録の Issue のコメントに、**直した判断と、理由**を書きます（元の判断は、消さずに残します）。

### 3. 考える

- 「あなたが頼んだ」カードでも、拒否や、確かめてから許可になったものはあるか。それは、なぜか。
- 「AI が提案した」カードを、**頼んでもいないのに**、AI が提案してきたとき、何に注意するか。
- 迷ったとき、**許可する側と、拒否する側**の、どちらに倒すか。それは、なぜか。

## 振り返り

- 判断の観点（取り消せるか／範囲／外へ出るか／秘密に触れるか／分かるか）のうち、いちばんよく使ったのはどれか。
- 「分からないから、許可しない」は、正しい判断か。
