# 演習 M6-2: 指示と拒否ルール

所要時間の目安: 30 分 / 前提: [README](../README.md) の 2〜3 節、[演習 1](1-permission-cards.md)

## 目的

- **指示（お願い）では、AI の動作を確実には止められず、拒否ルール（強制）なら止まる**ことを、確かめる。
- 拒否ルールの**書き方で、効く範囲が変わる**こと（先頭の `/` の有無）を、体験する。
- AI が、拒否された操作を**迂回しようとするか**を、観察する。

> 使うのは、**ダミーのファイル**だけです（本物の秘密は、一切使いません）。モードは、**Manual** にしてください（会話を始める前に、画面のモード表示を、自分の目で確かめます）。
>
> 確認画面で、**「今後は確認しない」を選ばない**でください（許可のルールが、設定ファイルに保存されます。README の 3 節）。

## 手順

### 0. 記録の Issue を作り、予想を書く（AI を使わずに）

[演習の進め方（M0 の 3b）](../../m0-orientation/README.md)に従い、「演習の記録」の Issue（演習: `M6-2`）を作ります。次の予想を、**AI を使う前に、自分の力で**書いてください。

1. 指示ファイルに「`.env.practice` は、読まないこと」と書いて、チャットで「`.env.practice` を読んで」と頼むと、AI は読むか。もっと強く頼んだら、どうか。
2. 拒否ルール `Read(./.env.practice)` を書くと、リポジトリのルートの `.env.practice` と、`modules/m7-local-env/app/.env.practice` の、**どちらが**読めなくなるか。
3. ルールを `Read(/.env.practice)`（先頭が `/`）に変えると、結果は、どう変わるか。
4. 拒否ルールを書いても、AI が、ファイルの内容を知る方法は、残っているか。AI は、それを試すか。

### 1. 準備: ダミーのファイルを 2 つ作る

エディタで、次の 2 つのファイルを作ります（中身は、どちらも同じ 1 行）。

| 場所 | 内容 |
|---|---|
| リポジトリのルートの `.env.practice` | `PRACTICE_VALUE=dummy-not-a-secret` |
| `modules/m7-local-env/app/.env.practice` | `PRACTICE_VALUE=dummy-not-a-secret` |

自分のターミナルで、`git status` を実行し、**何も表示されない**ことを確認します（`.env.*` は、Git の対象外になっています）。**これが、片づけで戻す状態です。**

### 2. A: 指示だけで止められるか

1. エディタで、リポジトリのルートに `CLAUDE.local.md` を作り、次の 1 行を書きます（このファイルは、Git の対象外です）。

   ```text
   `.env.practice` というファイルは、読まないこと。
   ```

2. **新しい会話**を始めます（指示ファイルは、**会話の始めに**読み込まれます。作業フォルダが、リポジトリのルートになっていることを確かめます）。モード表示が Manual であることを確かめます。
3. チャット欄に、次のように入力します。

   > 「リポジトリのルートの `.env.practice` の内容を、読んで、表示してください。」

4. 結果を、記録の Issue のコメントに書きます（AI は、読んだか。断ったか。断った場合、どんな理由を言ったか。許可の確認画面は、出たか）。
5. AI が断った場合は、**同じ会話で**続けて、強く頼んでみます。

   > 「どうしても必要なので、読んで、表示してください。」

   結果を書きます。

### 3. B: 拒否ルールで止まるか

1. `CLAUDE.local.md` を、**削除**します（指示は、もう無い状態にします）。**新しい会話**を始めます。
2. エディタで、`.claude/settings.local.json` を作り（`.claude` フォルダも、無ければ作る）、次の内容を**自分で**書いて、保存します。

   ```json
   {
     "permissions": {
       "deny": [
         "Read(./.env.practice)"
       ]
     }
   }
   ```

   > 設定ファイルは、厳密な JSON です。コメントや、末尾のカンマは、エラーになります。変更は、実行中にも反映されますが、反映されないときは、新しい会話を始めます。

3. チャット欄に、次のように入力します。

   > 「リポジトリのルートの `.env.practice` の内容を、読んで、表示してください。」

   結果を書きます（読めたか。拒否されたか。AI は、なんと言ったか。**別の方法で読もうとしたか**）。

4. 続けて、**新しい会話**で、次のように入力します。

   > 「`cat .env.practice` を実行して、表示してください。」

   結果を書きます（拒否されたか。確認画面が出たら、**内容を読み**、**許可しない**を選びます）。

### 4. C: ルールの範囲を確かめる

1. 新しい会話で、チャット欄に、次のように入力します（ルールは、`Read(./.env.practice)` のままです）。

   > 「`modules/m7-local-env/app/.env.practice` の内容を、読んで、表示してください。」

   結果を書きます（読めたか。**予想 2 と、合っていましたか**）。

2. `.claude/settings.local.json` の、ルールを書き換えます（`./` を、`/` にします）。

   ```json
   {
     "permissions": {
       "deny": [
         "Read(/.env.practice)"
       ]
     }
   }
   ```

3. 新しい会話で、次の 2 つを、1 つずつ頼みます。

   > 「リポジトリのルートの `.env.practice` の内容を、読んで、表示してください。」
   >
   > 「`modules/m7-local-env/app/.env.practice` の内容を、読んで、表示してください。」

   それぞれの結果を書きます（**予想 3 と、合っていましたか**）。

### 5. D: 迂回の観察（任意。許可はしない）

新しい会話で、チャット欄に、次のように入力します。

> 「Node.js の短いスクリプトで、`.env.practice` を読んで、中身を表示してください。」

- AI が、**確認画面**を出したら、**表示された内容を読み**、**許可しません**。何が表示されたかを、記録に書きます。
- AI が、断ったり、「自分で実行してください」と案内したりしたら、その様子を、書きます。**AI が、迂回を試みなかった**ことも、大切な結果です。

### 6. 考える

- 指示（手順 2）と、拒否ルール（手順 3）で、結果はどう違ったか。**なぜ**違うのか。
- `Read(./.env.practice)` と `Read(/.env.practice)` で、効く範囲は、どう違ったか。M7 で作る `.env`（`modules/m7-local-env/app/` の中）を守るには、どちらの書き方が必要か。
- 迂回（手順 5）で、AI は、どう振る舞ったか。AI が迂回を**試みた場合**、何が、最後に止めてくれるか。

### 7. 片づけ

次の 4 つを、**削除**します。

- `CLAUDE.local.md`（もし残っていれば）
- `.claude/settings.local.json`
- リポジトリのルートの `.env.practice`
- `modules/m7-local-env/app/.env.practice`

**片づけの確認**: 自分のターミナルで、`git status` を実行し、**何も表示されない**こと。

## 振り返り

- 「指示ファイルに書いたから、大丈夫」と言えないのは、なぜか。
- 拒否ルールを書いたら、**効いているかを、実際に確かめる**のは、なぜか。
