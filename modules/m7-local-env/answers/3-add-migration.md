# M7-3 の答えと解説

> 先に、自分の予想と考えを書き残してから読んでください。

## 設問4〜6: 結果

### ヒント

- 新しいマイグレーションは「差分」。すでにあるものは、触らない。
- 適用した記録は、データベースの側にも残っている。

### 答え

| 操作 | 結果 |
|---|---|
| 新しいマイグレーションを適用 | `priority` 列が増える。**既存の 5 件のメモは残り**、`priority` の値は既定値の `0` |
| もう一度 `db:migrate` | **何も適用されない**（すでに適用済みと記録されているため） |

マイグレーションを足すことで、**データを消さずに**、データベースの形だけを変えられます。

## 振り返りの答え

- **新しいファイルにした理由**: `create_notes.sql` を書き換えると、すでにそれを適用済みの環境には反映されない（演習 4）。新しいファイルなら、**適用済みの環境にも、これから作る環境にも、同じ順序で**適用できる。
- **「履歴」と呼ぶ理由**: ファイルが日時順に並び、データベースが**どこまで適用したか**を記録している。ファイルの並びを見れば、データベースの形が**どう変わってきたか**が分かる。バージョン管理（Git）が、コードの履歴を残すのと同じ考え方。

## 補足: 作った直後の確認

`npx supabase migration list --local`（または Studio）で、どのマイグレーションが適用済みかを確認できます。`--local` を付け忘れると、クラウドのプロジェクトを探してエラーになります。
