# 演習 M7-2: 壊して、作り直す

所要時間の目安: 15 分 / 前提: [演習 1](1-explore-and-keys.md)（片づけまで終えていること）

## 目的

「ローカルなら、壊しても作り直せる」ことを体験する。

## 手順

作業は `modules/m7-local-env/app` の中で行います。

### 0. 記録の Issue を作り、予想を書く

[演習の進め方（M0 の 3b）](../../m0-orientation/README.md)に従い、「演習の記録」の Issue（演習: `M7-2`）を作ります。次の予想を、**実行する前に**書いてください。

- Studio でデータを消したあと、`npm run db:reset` を実行すると、データはどうなるか。
- 自分で追加したデータは、どうなるか。

### 1. わざと壊す

Studio の **Table Editor** で `notes` を開き、次の操作でデータを**すべて削除**します。

1. 表の見出しの、いちばん左の**チェックボックス**を押す（全行が選ばれる）。
2. 右上に出る赤いボタン「**Delete 5 rows**」を押す。
3. 確認の表示（「Confirm to delete the selected rows」）の「**Delete**」を押す。

画面に「This table is empty」と出て、画面下が「0 records」になります。ターミナルでも確認します。

```bash
npm run notes
```

「メモは 0 件です。」になることを確認します。

### 2. 作り直す

```bash
npm run db:reset
npm run notes
```

何件に戻りましたか。どのファイルのデータが入りましたか。

### 3. 自分のデータを足して、もう一度作り直す

```bash
npm run insert -- --admin "自分で足したメモ"
npm run db:reset
npm run notes
```

自分で足したメモは、残っていますか。

### 4. 考える

- 「自分で足したメモが消える」のは、困ることか。それとも利点か。
- 開発で使う、テスト用のデータを、チームの全員が同じにしておく利点は何か。
- `seed.sql` に、実在の人の名前やメールアドレスを入れてはいけないのは、なぜか。

### 5. 片づけの確認

手順 3 の最後で `db:reset` をしているので、データは初期状態です。「メモは 5 件です。」と表示されることを確認します。

## 振り返り

- `db:reset` が行うことを、一言で言うと。
- 本番のデータベースで、同じことをしたらどうなるか。

答えは [answers/2-reset-and-seed.md](../answers/2-reset-and-seed.md)。見たあと、記録の Issue に「答えを見て気づいたこと」をコメントし、Issue を閉じます。
