# M8-2 の答えと解説

> 先に、自分の予想と考えを書き残してから読んでください。

## 設問: 3 つのテストと、結果

### ヒント

- RLS を無効にすると、「ルールによる制限」がなくなる。何ができるようになるか。
- 3 つのテストのうち、「制限されること」を確かめているのは、どれか。

### 答え

`test/db/rls.test.ts` の 3 つのテスト:

| テスト | 確かめること | RLS 無効のとき |
|---|---|---|
| 匿名の鍵で、メモを読める | 読むことが許されている | 通る（制限がなくなっても、読める） |
| **匿名の鍵では、メモを追加できない** | 追加が拒否される（RLS の効果） | **失敗する**（追加できてしまう） |
| サーバー用の鍵で、メモを追加できる | サーバーは追加できる | 通る |

失敗のメッセージは、`追加が拒否されるはずが、成功してしまった` です。

「制限されること」を確かめるテストが、制限の消失を検出しました。

## 手順 4: 考える

### このテストが無かったら

気づけるのは、**誰かが実際に、不正に追加したとき**など、被害が出てからになりやすい。RLS は、画面に出ない設定なので、普段は、誰も見ません。**「見えない設定」こそ、テストで守る**価値があります。

### 本番や staging の実際の設定も、確かめられるか

**このテストだけでは、確かめられません。** このテストが調べているのは、**自分のパソコンの、ローカルのデータベース**です。ローカルは、マイグレーションのファイルから作られるので、「ファイルの内容が正しいか」は確かめられます。しかし、本番や staging が、**そのファイルのとおりになっているか**（誰かが画面から設定を変えていないか）は、別に確かめる必要があります。

## 振り返りの答え

- **設定をテストする**とは: コードを書かなくても、「ルール（設定）が、期待どおりに働いているか」を、実際に操作して確かめること。今回は、「匿名の鍵では追加できない」という結果を、テストにした。
- **ローカルと本番の違い**: 同じではない。ローカルのテストが通っても、本番の設定が正しいとは限らない。M7 で学んだ、環境のずれ（ローカルと本番のずれ）と同じ考え方。本番の設定の確認は、別の手段（実機の確認、検査）で行う。
