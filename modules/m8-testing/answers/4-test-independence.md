# M8-4 の答えと解説

> 先に、自分の予想と考えを書き残してから読んでください。

## 設問: 素朴なテストの結果

### ヒント

- 初期状態は 5 件。素朴なテストは「追加すると 6 件になる」はず、と書いている。
- 同じファイルの、**素朴なテストより前に実行されるテスト**が、何をしているか。

### 答え

素朴なテストは、**失敗します**。

```
Expected: 6
Received: 7
```

### 原因

同じファイルの、2 つ目のテスト（「メモを追加すると、一覧に表示される」）が、**すでに 1 件追加**しています。

| 時点 | 件数 |
|---|---|
| 初期状態 | 5 件 |
| 2 つ目のテストの後 | 6 件 |
| 素朴なテストが追加した後 | **7 件**（期待は 6 件） |

素朴なテストは、「5 件から始まる」という**前提**に、暗黙に頼っていました。その前提を、**前のテストが壊しました。**

## 独立した書き方

```ts
const before = await items.count();   // 追加の前の件数を、自分で数える
...
await expect(items).toHaveCount(before + 1);   // 「1 件増える」を確かめる
```

「今、何件あるか」に依存せず、**自分の操作の前後の差**だけを確かめます。そのため、いつ実行しても、何件から始まっても、通ります（連続で 2 回実行しても通ることを確認します）。

## 手順 6: 考える

### 並列に実行したら

複数のテストが同じデータベースを同時に更新するので、件数が**実行のたびに変わり**、結果が不安定になります。そのため、`playwright.config.ts` は `workers: 1`（1 つずつ順番に実行）にしています。**独立したテストなら、並列にして速くできる**可能性があります。

## 振り返りの答え

- **テストが独立している**とは: ほかのテストの実行、順番、結果に左右されず、**単独で実行しても、どの順番でも、同じ結果になる**こと。
- **`db:reset` と、独立させることの違い**:
  - 「テストの前に `db:reset` する」は、**前提を揃える**手段。手間がかかり、テストの途中の影響は防げない（今回のように、同じ実行の中で、前のテストが状態を変える）。
  - 「テスト自体を独立させる」は、**前提に頼らない書き方**。どちらも使うが、基本は、独立させる。

## 補足: 不安定（flaky）なテスト

同じコードなのに、通ったり落ちたりするテストを、不安定（flaky）といいます。原因は、順番への依存、時間（待ち時間の不足）、共有している状態などです。不安定なテストは、「どうせまた落ちている」と無視されるようになり、**本当の失敗も見逃される**ため、見つけたら、すぐ直します。
