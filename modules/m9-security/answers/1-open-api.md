# M9-1 の答えと解説

> 先に、自分の予想と観察を書き残してから読んでください。この手順（`curl` の結果）は、教材の作成時に、実際に確かめています。

## 予想と結果

### ヒント

- `curl` は、**ブラウザの画面を使わず**、サーバーに、直接、リクエストを送る道具。
- サーバーが、リクエストを**誰から来たか確かめるか**が、分かれ目。

### 答え

| 送った先 | 結果 | 意味 |
|---|---|---|
| ログインなし（3100） | **`HTTP/1.1 303 See Other`**（`location: /`）。ブラウザで再読み込みすると、**`added-by-curl` が増えている** | **追加できてしまった**。サーバーは、誰からのリクエストかを、確かめていない |
| ログイン付き（3101） | **`HTTP/1.1 401 Unauthorized`**。一覧に、**増えていない** | サーバーが、**「ログインしていない人は、お断り」**と判断した |

### 画面の「追加フォーム」について

ログイン付きの画面では、ログインしていないと、追加フォームが**出ません**。しかし、**追加が断られたのは、フォームが出ないからではありません**。`curl` は、画面を使わないので、フォームの有無とは、無関係です。**サーバーが、401 で断ったから**です。

## 手順 5: 考える

- **断ったのは、サーバー**。画面のフォームが出ないことは、守りには、なっていない。
- **「画面にボタンを出さなければ、操作されない」と言えない理由**: 画面は、**利用者のブラウザの中**にある。利用者は、画面を使わなくても、**サーバーの住所（URL）と、送る内容が分かれば**、直接、リクエストを送れる。ブラウザの開発者ツールや、`curl` のような道具で、簡単にできる。

## 振り返りの答え

- **画面は、誰のものか**: 利用者のもの。利用者が、自由に、見て・書き換えて・使わずに済ませられる。サーバーを、画面なしで呼ぶことも、できる。
- **守りは、どこで行うか**: **サーバー**で行う。画面の見た目（ボタンを隠す、入力欄を出さない）は、使いやすさのためで、**守りではない**。

## 補足

- **日本語のタイトルで文字化けする**理由: 日本語の Windows のターミナルが、`curl` に、UTF-8 ではない文字コードで、文字を渡すことがあるため。英数字なら、起きない。
- この「誰でも追加できる」穴は、M8 までのサーバーに、**わざと残してあります**（E2E テストの題材にするため）。本番のシステムでは、あってはならない状態です。
