# M9-3 の答えと解説

> 先に、自分の予想と観察を書き残してから読んでください。生徒・講師の動作と、Cookie の改ざんの結果は、教材の作成時に、自動テスト（本物の Supabase の認証を使う）で確かめています。ブラウザのコンソール・開発者ツールの操作は、確認していません。

## 観察の結果

### ヒント

- 認証は「誰か」。認可は「何をしてよいか」。
- サーバーは、**確かめた情報**で判断する。

### 答え

| 手順 | 結果 |
|---|---|
| A: 生徒でログイン | **ログインできる**。画面に、**追加フォームは出ない**。「メモを追加できるのは、講師（teacher）だけです。」と表示される |
| B: 生徒が、コンソールから追加を試みる | ステータス **`403`**（Forbidden: 権限がない）。**追加されない** |
| C: `role=teacher` を書き足して送る | **やはり `403`**。**役割は、偽装できない** |
| D: 講師でログイン | 追加フォームが出て、**メモを追加できる** |
| E: Cookie の値を書き換えて再読み込み | **ログインが、無効になる**（「ログインしていません」の表示になる）。追加を試みると、`401`（認証されていない） |

## 手順 7: 考える

- **サーバーが、役割を判断する根拠**: **ログインの Cookie の中身を、認証の仕組み（Supabase Auth）に確かめ、その結果として得たユーザー情報**（サーバー側でだけ書き換えられる、役割）。フォームに書いた `role=teacher` は、**読んでいない**から、効かない。**画面から送られた値は、利用者が自由に書き換えられるので、信じない**。
- **「ログインできた」と「何でもできる」の違い**: **認証**は、「あなたは、**誰か**」を確かめること（生徒として、ログインできた）。**認可**は、「あなたは、**これをしてよいか**」を判断すること（生徒は、追加してはいけない）。**認証のあとに、認可がある**。生徒は、認証されたが、認可されなかった（403）。
- **Cookie を書き換えると、ログインが無効になる理由**: Cookie の中身は、**認証の仕組みが署名した、証明書のようなもの**。サーバーは、リクエストのたびに、その署名が**正しいか**を確かめる。**1 文字でも書き換えると、署名が合わなくなり、偽物と判断される**。利用者が、自分で、別の人の Cookie を、作り出すことは、できない。

## 振り返りの答え

- **認証と認可**: 認証は、**誰か**を確かめる（ログイン）。認可は、**何をしてよいか**を判断する（役割による、操作の許可）。
- **画面の値を信じず、サーバーが確かめた情報を使う理由**: 画面から送られる値は、**利用者が、自由に書き換えられる**から。信じてしまうと、**誰でも、「私は管理者です」と名乗れてしまう**。

## 補足

- 401 と 403 の違い: **401** は「あなたが、**誰か分からない**（ログインしていない、または、無効）」。**403** は「あなたが誰かは、分かった。でも、**してはいけない**」。
