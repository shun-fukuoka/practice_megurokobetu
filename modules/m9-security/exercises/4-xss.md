# 演習 M9-4: XSS

所要時間の目安: 25 分 / 前提: [演習 3](3-authn-authz.md)（片づけまで終えていること。テストユーザーがあること）

## 目的

- 画面に出す文字の中に**スクリプトが紛れる**と、何が起きるかを、見る。
- **エスケープ**の効果と、**HttpOnly** が守るものを、確かめる。

> コードは書きません。**危険な画面は、この演習のために、わざと作ったものです。** 自分のパソコンの中だけで動かし、終わったら止めます。**実在のサイトや、他の人に、試してはいけません。**

## 手順

作業は `modules/m7-local-env/app` の中で行います。

### 0. 記録の Issue を作り、予想を書く（自分の力で）

[演習の進め方（M0 の 3b）](../../m0-orientation/README.md)に従い、「演習の記録」の Issue（演習: `M9-4`）を作ります。次の予想を、**実行する前に**書いてください。

メモのタイトルに、次の 1 行を入れて追加します（画像を読み込めなかったときに、スクリプトを実行する、という内容です）。

```text
<img src=x onerror="document.title=document.cookie">
```

1. **安全な画面**（エスケープする）で、この 1 行は、画面に、どう表示されるか。
2. **危険な画面**（エスケープしない）では、何が起きるか。
3. 危険な画面で、スクリプトは、ログインの Cookie（`lab_session`）を、**読み取れる**か。

### 1. 危険な画面も有効にして、サーバーを起動する

```bash
npm run dev:secure:unsafe
```

起動したままにします。起動時の表示に、「演習専用: 危険な画面 /unsafe が有効」と出ることを確認します。

### 2. 講師でログインして、メモを追加する

http://127.0.0.1:3101 を開き、`teacher@test.local` と `practice-pass-123` で、ログインします。タイトル欄に、上の 1 行（`<img src=x …>`）を、**貼り付けて**、「追加」を押します。

### 3. 安全な画面で見る

追加後の画面（`/`）の、メモの一覧を見ます。

- その 1 行は、どう表示されていますか。（**文字として**表示されているか）
- ブラウザの**タブの名前**は、変わっていますか。

### 4. 危険な画面で見る

ブラウザで、次を開きます。

```text
http://127.0.0.1:3101/unsafe
```

- ブラウザの**タブの名前**は、どうなりましたか。
- 書き換えられた名前に、何が含まれていますか。（`lab_session` は、含まれていますか。`lab_theme` は、どうですか）

### 5. 考える

- 安全な画面と、危険な画面の違いは、何か。**何が、実行を防いだ**のか。
- スクリプトが読み取れた Cookie と、読み取れなかった Cookie の違いは、何か。（演習 2 を、思い出す）
- **HttpOnly があれば、XSS は、もう安全**と言えるか。（ヒント: スクリプトは、利用者の代わりに、**操作**することは、できないか。ブラウザは、Cookie を、自動で送る）

### 6. 片づけ

- サーバーを、**Ctrl+C** で止めます（**危険な画面は、使い終わったら、必ず止めます**）。
- 追加したメモを消すため、データベースを初期状態に戻し、テストユーザーを作り直します。

  ```bash
  npm run db:reset
  npm run seed:users
  ```

## 振り返り

- XSS は、何が、誰のブラウザで、実行される攻撃か。
- 主な対策は、何か。HttpOnly は、その中で、どういう位置づけか。
