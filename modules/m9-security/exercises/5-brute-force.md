# 演習 M9-5: ブルートフォースとボット対策

所要時間の目安: 20 分 / 前提: [演習 4](4-xss.md)（片づけまで終えていること。テストユーザーがあること）

## 目的

- ログインの**失敗が続いたとき**、サーバーがどう振る舞うかを、見る。
- **レート制限**と、**CAPTCHA（Turnstile など）**の、役割と限界を、説明できるようにする。

> コードは書きません。画面で、間違ったパスワードを入力するだけです。

## 手順

作業は `modules/m7-local-env/app` の中で行います。

### 0. 記録の Issue を作り、予想を書く（自分の力で）

[演習の進め方（M0 の 3b）](../../m0-orientation/README.md)に従い、「演習の記録」の Issue（演習: `M9-5`）を作ります。次の予想を、**実行する前に**書いてください。

1. 間違ったパスワードで、続けてログインを試すと、何回目で、どうなるか。
2. そのあと、**正しいパスワード**を入力したら、ログインできるか。
3. 存在しないメールアドレスで試したときの、画面のメッセージは、存在するメールアドレスで試したときと、**同じか、違うか**。

### 1. サーバーを起動する

```bash
npm run dev:secure
```

起動したままにします。ブラウザで http://127.0.0.1:3101/login を開きます。

### 2. 間違ったパスワードで、続けて試す

メールアドレス `teacher@test.local`、パスワード（**間違ったもの**。例: `wrong1`、`wrong2`、…）で、「ログイン」を、**6 回**続けて押します。回ごとの画面のメッセージを、記録に書きます。

### 3. 正しいパスワードで、試す

そのまま、メールアドレス `teacher@test.local`、パスワード `practice-pass-123`（**正しいもの**）で、「ログイン」を押します。ログインできましたか。画面のメッセージは、何でしたか。

### 4. 制限を解く

次のどちらかで、制限を解きます。

- **1 分間、待つ**（制限は、時間がたつと解ける）。
- ターミナルで **Ctrl+C** を押してサーバーを止め、もう一度 `npm run dev:secure` で起動する（**失敗の記録は、メモリの上だけ**なので、再起動で消える）。

もう一度、正しいパスワードで、ログインを試します。

### 5. 存在しないメールアドレスで試す

ログアウトして、サーバーを再起動し（記録を消す）、メールアドレス `nobody@test.local`（存在しない）、パスワード `whatever-123` で、ログインを試します。画面のメッセージを、手順 2 の 1 回目と**比べて**ください。

### 6. 考える

- 制限が働いたあと、**正しいパスワードでも、入れなかった**。これは、**攻撃者を止める**効果と、**本物の利用者を、一時的に締め出す**影響の、どちらもある。この両方を、どう考えるか。
- **レート制限だけでは、防ぎきれない攻撃**は、どんなものか。（ヒント: 攻撃者が、たくさんの場所から、1 回ずつ試したら）
- **CAPTCHA（Turnstile など）**は、そのとき、何をするか。README の「Turnstile の流れ」を見ながら、**自分の言葉で、流れを順に説明**する。
  - なぜ、トークンの検証を、**サーバー側**で行うのか。
- 手順 5 で、存在しないメールアドレスのとき、メッセージが**同じ**なのは、なぜか。

### 7. 片づけ

サーバーを、**Ctrl+C** で止めます（データベースは、変更していません）。

## 振り返り

- ブルートフォースとは何か。レート制限は、何を防ぐのか。
- ボット対策（Turnstile など）は、レート制限と、どう役割が違うのか。

答えは [answers/5-brute-force.md](../answers/5-brute-force.md)。見たあと、記録の Issue に「答えを見て気づいたこと」をコメントし、Issue を閉じます。
